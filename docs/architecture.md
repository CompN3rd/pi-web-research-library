# Architecture and bounds

One package declares a machine-specific browser/server pair and one Pi companion. The browser uses API v4 and the server uses API v3. Research tasks use public `pi-web.host/pi-sessions@1`; structured results use `pi-session-events@1`. There is no workspace provider, scheduler, private host route, runtime host import or Automations dependency.

- `src/browser/`: Library/Discover custom elements, transient drafts, strict peer clients and PDF.js range transport. All browser assets are inside `dist/browser/`.
- `src/domain/`: catalog schemas, validation, bibliography conversion, PDF geometry and protocol primitives. Client validation is not authority.
- `src/server/`: host-scoped catalog/evidence/task/manuscript persistence, discovery, verified PDF snapshots and text indexing. Only the host supplies workspace authority.
- `src/companion/workbenchTools.ts`: six bounded catalog tools, usable in ordinary Pi sessions; result submission needs an admitted hosted task. No alternate source discovery or demo runtime.
- `src/server-plugin.ts`: lifetime, versioned peer dispatch, reader expiry and capability resolution during `start()`, not activation.

## Library: ownership and composition

The **Library** panel is a reference/evidence/research/writing application, not a reference-manager connector. Its v1 catalog is `.pi-web/research-library/library.json`. All product workflows share it; historical formats are not loaded or migrated. The earlier pilot/synthetic runtime is removed, not retained behind a compatibility flag.

- `workbench.ts` and `workbenchValidation.ts` define strict records and full-state validation. References have stable IDs, citation keys/aliases, metadata, collections, reading/screening state, and up to 16 independently verified PDF attachments.
- `WorkbenchStore` owns bounded reads, per-canonical-workspace serialization, expected revisions, recovery and flushed atomic replacement. It rejects corrupt/unknown fields, stale external replacements observed before publication, invalid cross-references and unsafe paths. Missing-state reads do not create a catalog.
- `LibraryCatalog`, `LibraryResearch`, `LibraryWriting`, `WorkbenchText` and `LibraryDiscovery` compose through injected repository/codec/text/capability interfaces. `NativeWorkbench` routes strict operations using only host-resolved authority. Companion tools use ordinary Pi's trusted cwd, not a peer-supplied root.
- Citation.js implements portable bibliography conversion and CSL formatting; unsupported metadata is explicitly qualified as lossy. The browser owns transient forms and consent, not durable records or verified PDF identities. Independent metadata/evidence/manuscript drafts survive in-instance workspace switching; a destroyed element or page reload loses unsaved drafts.

The catalog is capped at 16MiB, 5,000 references, 10,000 evidence records, 200 tasks, 100 manuscripts, 1,000 collections and 100 saved searches. Reference/evidence/task/manuscript records additionally fit 190KiB UTF-8; scalar character limits do not override that aggregate limit. List pages contain at most 25 records and 192KiB including their envelope, with explicit `nextOffset`. Refreshable pagination is not a frozen catalog snapshot. The repository admits at most 64 queued operations per workspace and 256 in its process.

Imports are staged standard files (BibTeX, RIS, CSL-JSON), not vendor APIs. Catalog import input is limited to 1MiB and its complete preview to 192KiB; oversized previews require smaller batches. Selected original rows, format and exact file text determine replay identity. Modified/re-exported files are new imports. Duplicate candidates never silently overwrite existing records. Exports are capped at 2MiB and fail visibly rather than truncate.

Trash retains records and PDFs. Merge preserves a tombstoned loser and historical attribution; document identities are reference-scoped. A loser with active evidence cannot be merged, to avoid stranding that evidence. Restoring a reference must not introduce an active citation-key collision. Evidence deletion also retains the complete preceding record at `evidence/<id>.<revision>.json.deleted` before publishing the tombstone. Neither tombstones nor derivative caches are secure erasure or automatically garbage-collected.

These are trusted-workspace, single-writer guarantees. File fsync and atomic publication do not provide cross-process fencing, transactional power-loss recovery, or isolation from a hostile same-account process swapping ancestors between filesystem checks. Windows does not expose directory fsync through these Node APIs. Failures remain visible; recovery files are retained rather than silently overwritten.

## PDF transport and source identity

`library.pdf.open` resolves an attachment from the server catalog, then verifies its local file signature, declared size and SHA-256 while copying into a plugin-owned disk snapshot. A peer cannot supply an authoritative digest or path. Symlink traversal is rejected. Copy/hash work uses 256KiB pieces; source changes reject the open and remove its partial snapshot. An admitted snapshot remains the verified revision even if the source changes later.

Opaque reader IDs are scoped to the host's project/workspace/path tuple. There are at most four active or pending readers, each at most 128MiB. `pdf.read` bounds ranges to 256KiB and permits two concurrent reads per reader. `pdf.close` releases a snapshot; idle readers expire after two minutes. `dataDirectory/pdf-cache/` is reconstructible cache, not research state. Lifetime cancellation stops ingress/copying; disposal closes snapshots, and startup clears crash leftovers. There is no pilot `pdf.open` operation.

The browser requests base64 ranges through public peers, never a private URL. PDF.js may coalesce a larger range: the adapter fetches serial 256KiB pieces and accumulates **one range buffer up to the 128MiB document cap** before one PDF.js callback. At most 16 ranges may be queued. PDF.js retains additional document/rendering data; this is not a 256KiB browser-memory promise. Canvas limits are 16 million pixels, 16,384 pixels per dimension and device scale 2. Only trusted local PDFs should be opened.

The browser reader owns one canvas and one PDF.js text layer, with transient page/fit/tone/find state. `pdfReading.ts` contains pure fit and search-offset logic; `pdfViewerTemplate.ts` owns reader markup/styles. Resize observation is debounced and disconnected with the element. Render cancellation drains the previous canvas task before reuse; a same-page zoom retains the PDF page proxy rather than cleaning up an operator stream still in flight. Native dialog focus mode keeps that same reader and source alive. The workbench keeps catalog/draft ownership and source-hash checks; hiding its catalog or switching tabs does not remount the reader. Region selection and marker activation open the shared evidence editor inside Reader. The workbench's `annotation-open` attribute shortens the viewer on narrow layouts while its editor remains independently scrollable; the viewer's `focusPage()` returns keyboard focus after closing the editor. Keyboard and pointer marking converge on the same quote-capture/event path. Saved-annotation navigation uses only loaded records matching the active reference/document/hash. No evidence schema or server persistence changes are needed for this contextual editor.

Selected-text highlights and comments reuse the region-selection event and shared evidence editor/save boundary; they do not introduce a new evidence schema. A highlight is existing quote-kind evidence with an empty body, already accepted by server validation. The shared editor requires a body only when the immutable quote is blank. Adding or clearing a comment updates the same revisioned record without changing its anchor; quote-only markers are labeled Highlight and painted yellow. Source/index verification and immutable-anchor checks remain server-owned. `pdfTextSelection.ts` rejects selections outside the current text layer, reads shadow-aware composed ranges when available, and normalizes text geometry to the existing single-rectangle anchor. The keyboard/touch picker selects whole PDF.js runs in extraction order (at most 2,000 nonempty runs per page); quotes remain bounded to 16,000 characters. Tools reset on page/render/source changes and disconnect. Browser selection is convenience text, not a replacement for the verified server index required by document-backed evidence. Native mouse selection may expose a collapsed document-rescoped range in Chromium; only the actual composed range decides whether text was selected.

Reader Find extracts one page at a time, retaining only bounded match offsets (first 500 pages, at most 1,000 hits; a page above 1,000,000 extracted characters fails explicitly). Query changes, closing Find, disconnect and source changes invalidate pending results. It is browser-only convenience text, never the verified server index. Text-layer failures leave the visual page available with a warning. Page tone filters and evidence visibility affect only presentation. One-page rendering remains deliberate; continuous scrolling, PDF forms, embedded links and complete tagged-PDF accessibility are not implemented here.

PDF assets (worker, CMaps, standard fonts, WASM and ICC profiles) are module-relative and shipped with licenses. The host download URL provides an explicit fallback. A `research-pdf-ready` event after successful current-source rendering lets the notebook apply pending page backlinks. PDF geometry and quote capture have no dependency on an old annotation schema.

## Verified PDF text

`library.text.index` streams and verifies an attachment into a private temporary snapshot, then starts an isolated bundled `unpdf` worker. It processes pages sequentially, with two concurrent extractions, a 60-second termination deadline, a 256MiB old-generation heap ceiling per worker, 2,000 pages, 64,000 characters per page and two million characters per document. These are parser/work limits, not an overall RSS guarantee. Source handles, workers and snapshots are cleaned up on handled completion/cancellation. Parent request deadlines can be shorter.

The derivative index under `.pi-web/research-library/text/` binds source SHA-256, size and extraction version, with a text checksum. Reads validate structure/checksum and reverify the PDF before returning pages or hits. Ordinary reads fail on corrupt indexes; explicit rebuild re-verifies the source before regenerating only the derivative. This detects stale sources and accidental edits, not an actor who can rewrite the workspace. Browser text and model output never populate a verified index. PDF text order may differ from visual reading order; **OCR is not implemented**. Users must verify quotations, especially columns, formulas and tables.

Indexes are bounded to 8MiB each; at most eight text operations run per instance. Literal full-text search returns at most 50 page hits and scans at most 64MiB of indexes per call. Narrow corpora when that budget is exceeded. Companion passage/search tools read existing indexes without creating them. Output is capped at 64KiB, so an unusually large page fails visibly rather than being silently truncated.

## Agent results and writing

Tasks freeze at most 20 selected reference revisions, attachment hashes and evidence revisions. Preview constructs the exact bounded prompt without starting a model; confirmation durably records admission before public `sessions.run`. One task per workspace and four per service are tracked. Startup/connect waits are bounded to 30 seconds and initial-turn tracking to 30 minutes. Ordinary Pi tools are not sandboxed by research instructions.

`research_library_native_submit_result` uses a session-local request/acknowledgment protocol. The backend owns the public session connection, validates task/corpus/request identity, frozen evidence ownership and bounds, and acknowledges only after durable publication. Identical submissions are safe to replay. Native Pi session-manager IDs are **not** assumed equal to public host session IDs. Event delivery is ephemeral, not durable storage or agent completion. Other trusted extensions share the event bus; correlation is not authentication against malicious extensions.

Structured results (Markdown, attributed claims, cells and warnings) are limited to 128KiB. Persisted result, successful initial completion, human acceptance and manuscript application are distinct states. Provider failure, missing result, connection loss, restart or timeout cannot become accepted success. Corpus changes prevent acceptance or reuse as a current manuscript source; valid stale history remains readable. Shutdown stops observation, not the user's conversation; use Sessions to inspect/stop it. No automatic resubmission, evidence resolution or transcript scraping occurs.

Manuscripts use revisioned Markdown and stable citation bindings. Audit checks keys, aliases, selected references and stale accepted-task/evidence bindings; scientific entailment and quote fidelity require human review. A user can explicitly unlink a stale task while preserving draft text. CSL formats APA, Vancouver and Harvard; Vancouver follows first citation occurrence. Export supports Markdown, LaTeX, escaped HTML and portable JSON, not live Word/Google Docs fields or a typesetting engine.

File application is a separate consent boundary: explicit contained Markdown/text target, existing parent directory, expected target hash, manuscript revision and expiring preview token. The token binds generated output including bibliography changes. Before replacement, an exclusive backup preserves validated original bytes. Publication is atomic where supported, not compare-and-swap with unrelated editors or a cross-file catalog transaction. Source/config/library/recovery paths, symlinks, hard links and executable targets are rejected. A stale/restarted preview requires re-preview; exact no-write output replay is safe.

## Discovery and graph semantics

**Discover** offers local search, saved query recipes and metadata/claim connections without external service access. External search discloses only the confirmed query or OpenAlex work identity to fixed HTTPS Crossref/OpenAlex endpoints. There are no imported-URL fetches, redirects, credentials, vendor reference-manager connections, PDF downloads, background jobs or model calls. Requests are bounded to four concurrent calls, 15 seconds, 2MiB responses and 25 candidates/page; at most 20 pages can be requested explicitly. Provider failures are reported, not bypassed.

Selected cached results are imported as unverified metadata with provenance. DOI/exact-identity matches, including trash, remain unchanged. Workspace-bound preview receipts are limited to 16 and expire after 15 minutes. Local connections show shared author/tag metadata or model-claim co-occurrence, **not paper citations**; OpenAlex neighborhoods are separately labeled provider-reported citations. Counts are not scientific-quality judgments. Saved queries are manual recipes, not alerts, and selecting one clears prior results and disclosure consent.
