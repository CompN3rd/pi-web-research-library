It does not install a vendor connector or migrate the pilot. Local verification uses Windows / Node **24.19.0**, published **`@jmfederico/pi-web@1.202609.1`**, Pi **0.87.1**, and browser/server contracts v4/v3.

The integration checks below passed. Independent component reviews rechecked the catalog, research, writing and UI fixes. Two independent integrated reviewers then completed two remediation/recheck rounds and both returned **no remaining findings**. This is agent-assisted review, not an external security or legal certification. No failed coordinator run is counted as approval.

- `npm run verify` passed: **428 tests in 43 files**, typecheck, lint, build, native tool/import/source/asset validation and real-tarball execution. Distribution: **235 files, 11,186,034 bytes**. Package: **244 entries**, approximately **10.8 MiB** unpacked, below the 16 MiB / 4,096-entry limits.

- The real-tarball probe passed outside repository dependencies: actual native storage, standard bibliography import/export, CSL rendering and the bundled unpdf worker. Server network requests are forbidden in this probe.

The expanded real-browser scenario exercises compiled entries and nested module assets, a **12,583,518-byte authored PDF**, actual worker/canvas painting, native catalog creation/attachment, real server text indexing/search, mouse-created immutable quote evidence, reload/backlinks, and compiled companion catalog/passage tools. Local discovery, manually saved recipes and the honestly labeled connection diagram are also exercised. Legacy marking, reload, conversation consent/idempotency and two-tab conflicts remain covered.

Absent legacy-source probes intentionally return 404. Rapid full-page navigations can abandon best-effort PDF closes, so the harness explicitly releases old scenario readers through the public peer operation before starting the native scenario. Screenshots are ignored `.smoke/` artifacts, not packaged research data.

## Not established

The browser smoke uses the public plugin interfaces with a **test authority/transport adapter**, not a real session daemon. It does not establish full host catalog discovery, native service install/restart, the user's provider/extension profile, remote federation, or compatibility with host releases other than the exact published development target. No real provider calls, production state migration or npm publishing were tested or performed. Native structured-result capture and explicit human acceptance are implemented and exercised with the synthetic event adapter; that does not prove a live provider/companion session. Legacy question conversations still expose their receipt and direct the user to Sessions; native results do not automatically resolve those annotations. There is no automatic manuscript application.

Unit and distribution checks exercise the native Pi extension loader for both source and compiled companion entries, plus filesystem compatibility. An installed live session's companion discovery still needs an operator-controlled smoke during cutover. Public Crossref/OpenAlex behavior, provider policies/rate limits, live hosted native result delivery, larger real-world bibliography/PDF corpora and deployments outside the local platform remain unverified. OCR, live Word/Google Docs citation fields, cloud collaboration/sync, automatic alerts and vendor integrations are not implemented or claimed. Cross-process concurrent writers, hostile same-account filesystem mutation and power-loss durability are outside the claimed storage contract. The CI matrix is configured for Linux/Windows and Node 22.19/24; do not infer that remote CI passed from local results.
