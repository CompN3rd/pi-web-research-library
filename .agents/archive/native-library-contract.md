# Archived native Research Library implementation contract

Historical pre-greenfield lane handoff, not current instructions. Pilot/synthetic coexistence and the delegated workflow are retired. Current behavior is defined by `src/` and `docs/`; do not restore compatibility from this archive.

Operator accepted the research proposal with a decisive correction: this plugin REPLACES reference managers; no Paperpile/Zotero/Elicit/scite integration, vendor API, MCP, cloud sync dependency. Standard file import/export is portability, not a vendor connector. Implement a complete native local reference/evidence/research/writing workflow, not a staged demo. Preserve pilot and synthetic paths and behavior. No live host modifications, restart, publishing, or commits to the main checkout. Baseline contains pre-existing uncommitted work; preserve it.

## Shared contracts (parent-owned)

`src/domain/workbench.ts` supplies records, scalar validators, `LibraryRepository`, `BibliographyCodec`, `LibraryTextAccess`. Do not edit this file without supervisor agreement. Libraries are explicit independent native catalogs at `.pi-web/research-library/library.json`; pilot remains separately accessible. New workbench does not silently migrate pilot records. State retains tombstones; evidence deletion must ALSO retain `.deleted` recovery files. Read tools never write. Each service accepts an injected store and uses its serialized update callback, comparing expected entity revision. Do not treat model instructions as tool sandboxing.

Peer envelopes stay `{version:1,payload:...}`; parent dispatches operations below. Responses are JSON-serializable. Listings return `{items,total,nextOffset}`, with at most 25 records AND 192KiB of framed UTF-8 JSON. Full reference/evidence/task/manuscript records are capped at 190KiB, research results at 128KiB, and the whole catalog at 16MiB. Reference title/container1000, abstract16000, notes32000; evidence quote/body16000; task goal8000; manuscript markdown128000 are additional character maxima, not exemptions from byte limits. Reject unknown input fields, oversized/invalid content and stale updates. IDs are generated before mutation by browser (prefix + 32 hex characters); exact create retries return existing record only on matching content. No generic arbitrary commands or absolute workspace paths.

### Catalog service (catalog lane)

Export `LibraryCatalog` from `src/server/workbenchCatalog.ts`. Constructor `(store: LibraryRepository, codec: BibliographyCodec)`. `handle(root:string, operation:string, input:unknown, signal:AbortSignal):Promise<unknown>` supports:

- `library.list`: `{query?,offset?,collectionId?,tag?,readingStatus?,screening?,favorite?,trash?}` -> LibraryPage<LibraryReference>. Metadata search, deterministic ordering, bounded page, filters.
- `library.get`: `{id}` -> reference.
- `library.save`: `{id,expectedRevision,fields:ReferenceFields}` -> reference; expectedRevision 0 creates, >0 edits; preserve documents/provenance and previous citekey as alias. Citekey/alias collisions reject.
- `library.delete`, `library.restore`: `{id,expectedRevision}` -> reference soft tombstone/restored; never deletes PDFs.
- `library.duplicates`: `{}` -> `{pairs: [{leftId,rightId,reason}]}` bounded 100.
- `library.merge`: `{keepId,removeId,keepRevision,removeRevision}` -> reference, preserve files/tags/notes/aliases/provenance and mark loser deleted; evidence remains attributable, no silent loss. If cannot safely preserve referenced evidence, reject visibly rather than corrupt.
- `library.import.preview`: `{format:BibliographyFormat,text}` -> `{references:ReferenceFields[],warnings:string[],duplicateCandidates:[{index,referenceId,reason}],fingerprint:string}`.
- `library.import.commit`: `{format,text,indices:number[]}` -> `{added:string[],skipped:number,warnings:string[]}`; selected staged rows only, exact snapshot replay safe, duplicate candidates don't silently overwrite.
- `library.export`: `{referenceIds:string[],format:BibliographyFormat}` -> `{text,filename,mime}`.
- `library.attach`: `{referenceId,expectedRevision,path,label,sourceUrl,rights}` -> reference. Stream/hash bounded regular contained local PDF; reject symlinks/source change; never trust browser digest. Explicit relative path chosen by user. Max 16 docs/reference, each 128MiB.
- `collections.list`: `{}` -> LibraryCollection[].
- `collections.save`: `{id,expectedRevision,name,parentId:string|null}` -> collection. Reject cycles/duplicates; new id rev0.
- `collections.delete`: `{id,expectedRevision}` -> `{deleted:true}`; preserve or explicitly reject nested children, update affected ref revisions/membership.

Also own `src/server/workbenchStore.ts` and `src/domain/workbenchValidation.ts`: export class `WorkbenchStore implements LibraryRepository`, `readWorkbenchState(root,signal?)`; strict full-state validation and bounded reads, safe directory traversal, serialized operations (including reads vs rename on Windows), fsynced atomic publication, cap pending operations, no ignored errors. Missing state returns empty read without writing. Corruption fails closed. Tests exercise synthetic temp state.

### Evidence/research service (research lane)

Export `LibraryResearch` from `src/server/workbenchResearch.ts`. Constructor `(store: LibraryRepository, dependencies: {sessions:PiWebHostPiSessionsV1; events:PiWebHostPiSessionEventsV1; lifetime:AbortSignal; log:(message:string)=>void; text:LibraryTextAccess})`. `handle(context: Pick<ServerPluginPeerRequestContext,'project'|'workspace'>,operation,input,signal):Promise<unknown>`, plus `dispose():Promise<void>`.

- `evidence.list`: `{referenceId?,query?,kind?,status?,trash?,offset?}` -> LibraryPage<LibraryEvidence>.
- `evidence.save`: `{id,expectedRevision,referenceId,documentId,pdfSha256,page,rect,quote,body,kind,status,tags}` -> evidence. Anchor fields immutable after creation; refs/documents/sha/pages validated; null anchor supports unattached notes honestly. No model provenance fabricated. Deleted IDs cannot be recreated; restoration explicit if supported.
- `evidence.delete`: `{id,expectedRevision}` -> tombstoned evidence; `.deleted` recovery via store contract.
- `tasks.preview`: `{kind,goal,referenceIds}` -> `{corpusHash,prompt,referenceIds,warnings:string[]}`; frozen corpus selected <=20 references, <=64KiB prompt, untrusted evidence separation.
- `tasks.start`: `{id,kind,goal,referenceIds,expectedCorpusHash}` -> LibraryTask; explicit consent provided by UI; persisted idempotent admission, one active/workspace, four global.
- `tasks.list`: `{offset?}` -> LibraryPage<LibraryTask>; `tasks.get`: `{id}` -> task.
- `tasks.review`: `{id,expectedRevision,decision:'accepted'|'rejected'}` -> task; only validated result, corpus freshness, acceptance not execution success.
- Structured result submission is companion/session-local only, not arbitrary peer draft submission. Validate actual reference/evidence IDs, bounded claims/cells, run/session identity and frozen revisions; acknowledge only after durable write; replay duplicates safely. Use `pi-sessions.run` completion plus `pi-session-events` bridge or create/kickoff/agent_settled with full lifecycle correctness. Do not scrape host transcripts or private routes. Missing companion and lost connection must be visible. Later task results do not auto-resolve annotations.

Own `src/companion/workbenchTools.ts` exporting `registerWorkbenchTools(pi, readState:(root:string,signal?:AbortSignal)=>Promise<LibraryState>, text:LibraryTextAccess):void`. Names must not collide with legacy tools; native catalog_search, read_passage, search_text, get_evidence, resolve_citations, submit_result etc. No backend needed for read tools. Result tool uses hosted native events and fails visibly if not available. No direct cross-process state writes. Read current Pi extension docs/types and public event contract. Parent wires into companion entry.

### Bibliography/writing service (writing lane)

Export `bibliographyCodec: BibliographyCodec` from `src/domain/bibliography.ts`. Implement robust portable BibTeX, RIS, CSL-JSON parse/export and citation styles APA/Vancouver/Harvard; use installed Citation.js packages rather than brittle universal regex or invented formatted output. Standard files only, no vendor calls. Preserve data or warn on losses; cap imports/exports, escape all output, duplicate identity handling.

Export `LibraryWriting` from `src/server/workbenchWriting.ts`. Constructor `(store:LibraryRepository,codec:BibliographyCodec)`. `handle(root,operation,input,signal):Promise<unknown>` supports:

- `writing.list`: `{offset?,trash?}` -> LibraryPage<LibraryManuscript>.
- `writing.save`: `{id,expectedRevision,title,markdown,referenceIds,taskIds,style}` -> manuscript; taskIds must reference accepted, current results; identifiers resolved; revisions.
- `writing.delete`: `{id,expectedRevision}` -> tombstone.
- `writing.audit`: `{id}` -> `{issues:[{kind,message,key?}],citationKeys:string[],bibliography:string}`. Recognize Pandoc cite syntax outside code blocks; unknown/ambiguous keys, reference mismatches, stale tasks/evidence, quote problems clearly separate deterministic vs human judgments.
- `writing.export`: `{id,format:'markdown'|'latex'|'html'|'bundle'}` -> `{text,filename,mime}`. Bundle is portable JSON with manifest, draft, bibliography in multiple formats and evidence map. Warn drafts are not accepted truth and generated HTML has no executable untrusted markup. Include rendered bibliography/citation formatting, not just @tokens in HTML.
- `writing.apply.preview`: `{id,path}` -> `{expectedHash:string|null,text,diff:string,previewToken:string}`; no write. Independent expiring receipts bind the exact output, including bibliography changes, without one browser tab replacing another's preview.
- `writing.apply`: `{id,expectedRevision,path,expectedHash:string|null,previewToken:string}` -> `{path,backupPath:string|null,sha256}`. Explicit bounded Markdown/text target inside workspace, disallow library/pilot/source/recovery/config paths, symlinks, code/executable paths. Backup before atomic revision-checked replacement. Do not rewrite PDFs or vendor managed .bib. Handle output replay and failures visibly. No host private file APIs.

## Parent additions

- Native PDF text extraction: verified disk snapshot, isolated bounded `unpdf` worker, checksummed source/version-bound derivative index; no browser-extracted text accepted as verified, and no OCR claim. Local passage/search tools are read-only and never build missing indexes.
- `discovery.search`, `.related`, `.import`, `.saved.*` and `library.graph`: optional user-consented public Crossref/OpenAlex metadata, local saved query recipes, and honestly labeled local metadata/claim connections. These are not reference-manager/vendor connectors. Fixed HTTPS destinations only; no credentials, automatic PDF acquisition, background searches or model calls. Provider policy failures stay visible.
- Portable exports <=2MiB, catalog import input <=1MiB and staged preview <=192KiB, with visible rejection rather than silent truncation.
- Trusted-workspace filesystem boundary, not hostile-local-process isolation or cross-process fencing. PDF/index integrity checks and previews do not sandbox ordinary Pi tools.

## Lane topology

Multi-seam: catalog storage, research/result lifecycle, bibliography/writing, browser UI are independently testable. Four separate snapshot clones under OS temp; one writer each; all start from exact current source snapshot plus this contract. They must not mutate parent checkout, shared node_modules, package manifests, docs, build scripts, legacy files, or each other's seams. No nested subagents. Their NEW files are durable handoffs; run focused tests/lint, report inability to full-typecheck because other seams aren't yet present. Parent integrates only after handoffs, supplies PDF extraction/discovery and entry wiring, full tests/artifact/browser verification, and final review/remediation loop. Per-lane fresh reviewers inspect diffs and workers fix concrete findings before handoff. API changes require contact_supervisor first.
